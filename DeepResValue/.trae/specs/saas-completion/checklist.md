# 验收清单 (Checklist)

## 1. 前端鉴权与用户路由闭环
- [x] 成功注册新用户，能通过 `/register` 页面提交邮箱密码，并跳转至登录页。
- [x] 用户成功登录，能通过 `/login` 页面提交凭证，收到后端的 JWT Token，并自动重定向至首页或工作台。
- [x] 未登录用户尝试访问受保护路由（如 `/chat` 或 `/dashboard`）时，被前端路由守卫拦截并重定向至 `/login` 页面。

## 2. 用户控制台与账单明细 UI
- [x] 导航栏右上角能正确展示当前登录用户的头像、昵称（或邮箱前缀）以及实时积分余额。
- [x] 用户可以通过控制台（Dashboard）页面，清晰地查看到个人的基本信息和当前剩余积分。
- [x] 控制台内展示的账单流水列表组件能正确调用 `/api/points/ledger`，并以表格形式渲染出消费（扣减）和充值（增加）的明细记录。

## 3. 真实支付网关接入 (Backend)
- [x] 后端成功引入 `python-alipay-sdk` 并正确初始化支付宝客户端（包含 AppID、私钥、公钥和网关地址配置）。
- [x] 新增了 `Order` 数据库模型，并能够在使用 `/api/points/top-up` 时正确生成一条 `pending` 状态的充值订单记录。
- [x] 成功将现有的测试级 `/api/points/top-up` 改造为调用支付宝“电脑网站支付” API（`alipay.trade.page.pay`），并能向前端返回支付宝收银台的重定向 URL。
- [x] 成功实现了 `/api/webhooks/alipay` 异步通知路由，能够接收支付宝 POST 的表单数据。
- [x] 异步通知路由能够成功验签（验证支付宝公钥签名），确认 `trade_status` 为 `TRADE_SUCCESS` 后，将对应的本地 `Order` 状态更新为 `paid`。
- [x] 异步通知路由在验证支付成功后，能安全地在 `PointsLedger` 插入充值流水，并为用户账户增加相应积分。

## 4. 前端充值套餐页与扫码交互
- [x] 首页的定价套餐卡片（如“基础包”、“科研包”）点击事件已绑定。
- [x] 用户点击购买套餐后，前端能正确请求 `/api/points/top-up` 获取支付宝支付链接，并成功重定向至支付宝付款页面。
