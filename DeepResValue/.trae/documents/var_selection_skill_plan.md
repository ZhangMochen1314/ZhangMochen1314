# 核心变量筛选技能 (DeepResValue-VarSelection) 开发计划

## 1. 概述与目标
本计划旨在为 `DeepResValue` 智能体项目开发一个全新的定制技能（Custom Skill）：**DeepResValue-VarSelection**。
该技能专门用于实证分析前期的“变量筛选”工作。它将结合 **大模型（LLM）的语义理解能力** 与 **Lasso降维 + OLS显著性检验** 的传统计量统计方法，从用户提供的原始宽表中，智能挑选出既符合用户“研究主题”、又在统计上显著的核心解释变量与控制变量。

**核心约束：**
- 必须确保核心解释变量在回归中显著（p < 0.05 或 0.1）。
- 最终保留的控制变量数量一般不多于 10 个。
- 选出的解释变量和被解释变量必须在经济学/业务逻辑上高度契合用户的研究主题。

## 2. 当前架构分析
- **技能存放路径**：`/workspace/DeepResValue/skills/custom/`
- **技能定义格式**：每个技能是一个包含 `SKILL.md` 文件的独立目录。`SKILL.md` 头部使用 YAML 定义元数据（名称、描述、Python 依赖），主体部分使用 Markdown 编写系统提示词（System Prompt），指导智能体如何与用户交互并编写沙盒代码。
- **技术栈**：Python, `pandas`, `statsmodels` (用于 OLS 和 p 值), `scikit-learn` (用于 LassoCV 降维)。

## 3. 详细修改方案

### 3.1 创建技能目录与基础结构
- **路径**：`/workspace/DeepResValue/skills/custom/DeepResValue-VarSelection/`
- **文件**：`SKILL.md`

### 3.2 编写 `SKILL.md` 内容设计
`SKILL.md` 的内容将严格按照智能体执行的标准操作流程（SOP）进行设计，包含以下核心步骤的 Prompt 指令：

1. **元数据 (YAML Frontmatter)**
   - 依赖项声明：引入 `pandas`, `numpy`, `statsmodels`, `scikit-learn`。

2. **Phase 0: 意图与主题澄清 (Intent Clarification)**
   - 强制要求智能体在写代码前，必须询问用户的**具体研究主题**。
   - 探针读取数据：读取前 5 行及列名（`df.columns`）。
   - 如果用户没有指定**被解释变量 (Y)**，AI 需基于列名和主题为用户推荐并确认 Y。

3. **Phase 1: LLM 语义初筛 (Semantic Filtering)**
   - 智能体发挥大模型优势，仅凭列名字面意思和研究主题，人工剔除明显无关的列（如：身份证号、无关年份、其他无关业务指标）。
   - 挑选出 1-3 个最符合主题的“核心解释变量候选”以及一批“控制变量候选”。

4. **Phase 2: 统计降维与显著性过滤 (Lasso + OLS Pipeline)**
   - 指导智能体在沙盒中编写 Python 代码：
     - **预处理**：自动剔除缺失值过多的列，或对选定列进行简单的均值/中位数填充（确保能跑通回归）。
     - **Lasso 初筛**：如果控制变量候选极多，使用 `sklearn.linear_model.LassoCV` 进行正则化，剔除系数被压缩为 0 的控制变量。
     - **OLS 迭代筛选**：将保留的变量带入 `statsmodels.api.OLS` 进行多元回归。
     - **核心约束逻辑**：写一个 `while` 循环，每次剔除 p 值最大且不显著（p > 0.1）的**控制变量**，直到控制变量数量 $\le 10$，且所有控制变量相对显著。
     - **显著性保证**：在迭代过程中，**强制保留**核心解释变量，并最终输出它的 p 值。如果无论如何核心变量都不显著，代码应尝试更换候选的核心变量，或提示用户数据可能不支持该假设。

5. **Phase 3: 结果输出与学术解释**
   - 以 Markdown 格式输出最终选定的变量清单（Y, 核心 X, 控制变量集合）。
   - 结合用户的研究主题，用学术语言解释**为什么选这些变量**（经济学直觉）。
   - 输出最终的 OLS 回归结果摘要表（Summary）。

## 4. 假设与决策
- **假设**：用户上传的数据已经大致清洗过，或者包含能够被 `pandas` 正常读取的数值型数据。如果含有大量中文字符串分类变量，智能体需要生成 `pd.get_dummies` 等代码处理。这将在 Prompt 中作为“预处理注意点”提及。
- **决策**：不在技能目录下提供硬编码的 `.py` 脚本，而是将具体的“Lasso + OLS 迭代”逻辑以**伪代码或具体代码模板**的形式写入 `SKILL.md` 中，让大模型在运行时根据实际的列名动态生成和修改 Python 脚本。这符合现有技能（如 Panel 回归）的设计模式，具有更高的鲁棒性和灵活性。

## 5. 验收标准 (Verification Steps)
1. 技能文件 `SKILL.md` 成功创建并符合 YAML Frontmatter 规范。
2. 技能的提示词明确包含了“Lasso + OLS + LLM 语义过滤”的执行流。
3. 提示词明确约束了“核心变量必须显著”、“控制变量不多于10个”、“符合研究主题”三大条件。
