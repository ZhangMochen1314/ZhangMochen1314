# 深度研值 (DeepResValue) 内测阶段前端功能补齐计划

## 1. 摘要 (Summary)
在上一阶段的工作中，我们已经成功完成了**内测阶段核心缺失功能**的**后端**部分，包括新增 `Feedback` 数据表、反馈收集接口 (`/api/feedback`)、管理员一键加积分接口 (`/api/admin/add_credits`) 以及全局 500 错误拦截机制。
目前 SaaS 产品的内测准备工作**只剩下前端部分尚未完成**。本计划将详细列出前端如何对接已写好的后端接口，补齐管理后台、用户反馈、破冰引导和法律合规等四大缺失模块。

## 2. 当前状态分析 (Current State Analysis)
- **后端**：已完全就绪（包含管理员路由、反馈路由、全局异常处理等）。
- **前端**：
  1. 缺少一个方便管理员操作的后台页面 (`Admin.tsx`) 来为测试用户充值积分。
  2. 导航栏 (`Navbar.tsx`) 或界面中缺乏用户提交 Bug 和反馈的入口，导致用户遇到问题无法上报。
  3. 注册页面 (`Register.tsx`) 缺乏强制勾选的免责声明/服务条款，存在合规风险。
  4. 首次登录后的聊天界面 (`Chat.tsx`) 是空白的，缺乏对小白用户的“提示词推荐（破冰引导）”和遇到限流/错误的友好提示。

## 3. 提出的修改方案 (Proposed Changes)

### 3.1 创建轻量级超级管理员后台 (Admin Dashboard)
- **目标**：彻底解放您手动修改数据库的双手，直接在页面上一键为用户增加积分。
- **修改文件**：
  - 新增 `frontend/src/pages/Admin.tsx`。
  - 修改 `frontend/src/App.tsx`（或对应路由文件），添加仅对管理员可见的 `/admin` 路由。
- **实现细节**：
  - 调用 `GET /api/admin/users` 获取用户列表，展示邮箱、邀请码、积分等信息。
  - 在列表右侧提供【充值】按钮，点击调用 `POST /api/admin/add_credits` 为用户秒加积分。

### 3.2 完善用户报错与反馈闭环 (Feedback Modal)
- **目标**：提供反馈入口，拦截并记录测试用户的 Bug 和建议。
- **修改文件**：
  - 修改 `frontend/src/components/Navbar.tsx`（或其他全局组件）。
- **实现细节**：
  - 增加一个【🐞 报错/建议】按钮。
  - 点击后弹出一个 Modal 对话框，包含“问题类型”和“内容描述”。
  - 提交时调用已写好的 `POST /api/feedback` 接口。

### 3.3 破冰引导与全局异常提示 (Onboarding & Error Handling)
- **目标**：降低用户初次使用的门槛，体现“国奖直达车”的业务属性，并在系统繁忙时给予优雅提示。
- **修改文件**：
  - 修改 `frontend/src/components/Chat.tsx`（或核心对话组件）。
- **实现细节**：
  - **空状态（Empty State）**：当没有对话历史时，在屏幕中央展示 4 个预设的提示词卡片（例如：“帮我设计一个面板数据 DID 模型的实证方案”、“帮我梳理近三年关于'新质生产力'的文献”等），点击自动填入输入框。
  - **异常拦截**：如果请求后端时遇到 500 或 429 错误，在对话流中展示优雅的警告卡片，而不是白屏。

### 3.4 免责声明与合规 (Legal & Compliance)
- **目标**：规避数据隐私和 AI 生成结果不准确带来的潜在法律风险。
- **修改文件**：
  - 修改 `frontend/src/pages/Register.tsx`。
- **实现细节**：
  - 在注册按钮上方增加一个必选的复选框：`我已阅读并同意《服务条款》与《隐私政策》`。
  - 未勾选则禁用注册按钮。

## 4. 假设与设计决策 (Assumptions & Decisions)
- **复用现有 UI 框架**：Admin 页面、Feedback 弹窗将直接复用当前的 Tailwind CSS 和现有组件样式，保持极简和高效，不引入新的复杂组件库。
- **无感迁移**：前端的修改不会影响目前落地页 (`Landing.tsx`) 和主题切换的核心逻辑，纯粹作为补充模块集成。

## 5. 验证步骤 (Verification Steps)
1. 访问前端 `/admin` 路由，确认可以看到用户列表并能成功测试加分功能。
2. 登录新账号，检查 `Chat.tsx` 页面是否出现了 4 个推荐的提示词卡片。
3. 点击导航栏的反馈按钮，提交一条测试建议，检查前端是否提示成功（并通过网络面板确认接口调用成功）。
4. 在注册页面测试，如果不勾选“服务条款”，注册按钮应处于不可点击状态。
