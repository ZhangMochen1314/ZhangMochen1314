# 深度研值 (DeepResValue) 内测阶段核心缺失功能排查与实施计划

## 1. 摘要 (Summary)
本项目已经成功实现了从火山引擎到阿里云架构的迁移、落地页的全面美学重构、微信扫码手动计费闭环、裂变邀请码机制以及核心的沙箱交互能力。
然而，作为一个即将向真实 C 端用户（甚至可能产生费用的早期采纳者）开放的 **SaaS MVP (内测版本)**，在运营管理、用户反馈、法律合规及容错体验上仍存在明显的断层。本计划旨在梳理出上线前必须补齐的最后几块拼图。

## 2. 当前状态分析 (Current State Analysis)
- **已就绪模块**：JWT 鉴权（含环境变量配置）、沙箱 7 天定时清理任务、单文件 50MB 且最多 5 个的前端限制、基于 LLM Token 消耗的积分预扣费拦截逻辑、裂变邀请发积分逻辑、7 套多主题美化落地页。
- **当前核心痛点**：
  1. 充值依赖用户加您微信，您必须通过**手动执行 SQL 语句**来修改数据库加积分。内测用户一多，这种操作极易出错且耗费巨大精力。
  2. 测试期用户必然会遇到模型幻觉、代码报错或数据加载失败，但目前没有任何反馈报错入口，用户遇到问题可能直接流失。
  3. AI 医疗/教育/科研产品必须具备免责声明，目前注册流程缺乏强制同意条款。
  4. 首次登录后的 Chat 界面如果是完全空白的，很多小白用户（比如没有编程基础的文科生）不知道第一句话该怎么问。

## 3. 提出的修改方案 (Proposed Changes)

为了让 DeepResValue 顺利且安全地度过内测期，建议补充以下 4 个核心模块：

### 3.1 轻量级超级管理员后台 (Admin Dashboard)
**目标**：彻底解放您手动修改数据库的双手。
- **后端 (`backend/app/auth/router.py` & `models.py`)**：
  - 新增 `User.is_admin` 字段（布尔值，默认 False，您自己的账号设为 True）。
  - 提供 `/api/admin/users` 接口（分页列出所有用户，支持通过邮箱或微信搜索）。
  - 提供 `/api/admin/add_credits` 接口（一键为指定用户增加额度）。
- **前端 (`frontend/src/pages/Admin.tsx` 新增)**：
  - 一个仅对管理员可见的受保护路由 `/admin`。
  - 包含一个简洁的表格：显示【用户ID】、【注册邮箱】、【邀请码】、【当前积分】、【注册时间】。
  - 每行右侧提供一个【充值】按钮，点击输入数字即可秒加积分。

### 3.2 用户报错与反馈闭环 (Feedback Loop)
**目标**：留住遇到 Bug 的测试用户，收集真实使用痛点。
- **后端 (`backend/app/feedback/` 新增模块)**：
  - 创建 `Feedback` 数据库表（字段：`id`, `user_id`, `type` [bug/suggestion], `content`, `created_at`）。
  - 提供 `POST /api/feedback` 接口接收数据。
- **前端 (`frontend/src/components/Navbar.tsx` & 新增弹窗)**：
  - 在顶部导航栏或聊天输入框旁增加一个明显的【🐞 报错/建议】按钮。
  - 点击弹出一个 Modal，让用户填写遇到的问题。
  - （可选升级）管理员后台可以查看到这些反馈。

### 3.3 免责声明与合规 (Legal & Compliance)
**目标**：规避数据隐私和 AI 生成结果不准确带来的潜在法律风险。
- **前端 (`frontend/src/pages/Register.tsx`)**：
  - 在注册按钮上方增加一个复选框（Checkbox）：`我已阅读并同意《服务条款》与《隐私政策》`。
  - 未勾选则禁用注册按钮。
- **前端静态内容**：
  - 补充两个极其精简的静态文本弹窗或页面，说明：“本产品由 AI 驱动，分析结果仅供参考，不构成绝对的学术/商业决策依据；用户上传的分析数据承诺不会被用于非法用途。”

### 3.4 破冰引导 / 提示词推荐 (Onboarding & Empty State)
**目标**：降低用户初次使用的认知门槛，体现“国奖直达车”的业务属性。
- **前端 (`frontend/src/components/Chat.tsx`)**：
  - 当当前对话列表（`messages`）为空时，不要只展示一个空荡荡的输入框。
  - 在屏幕中央展示 4 个可点击的【示例提示词卡片】：
    1. *"我想研究数字化转型对企业创新的影响，帮我设计一个面板数据 DID 模型的实证方案。"*
    2. *"帮我找一份 2015-2023 年中国 A 股上市公司的 ESG 评级数据。"*
    3. *"给我看一下数据的基本描述性统计，并画出核心变量的分布图。"*
    4. *"帮我梳理近三年关于'新质生产力'的核心中文顶刊文献。"*
  - 用户点击卡片后，直接将文字填入输入框并自动发送。

### 3.5 全局异常拦截 (Global Exception Handling)
**目标**：防止后端崩溃导致的“死机”感，给予优雅提示。
- **后端 (`backend/app/gateway/app.py`)**：
  - 注入 `@app.exception_handler(Exception)`，捕获未预料的 500 错误，并返回友好的 JSON（如 `{"error": "系统繁忙，请稍后再试或点击顶部反馈按钮联系管理员。"}`）。
- **前端 (`frontend/src/components/Chat.tsx`)**：
  - 对 429 限流（Rate Limit）或 500 报错进行 UI 捕获，在对话流中输出带有 `t.accent1` 警告颜色的文本，而不是让前端直接白屏或没反应。

## 4. 假设与设计决策 (Assumptions & Decisions)
- **极简原则**：内测阶段时间宝贵，所有的管理后台和反馈收集都以**最快、最实用**的方式实现，不追求过度设计（例如不搞复杂的工单回复系统，只做单向收集）。
- **手动充值的妥协**：既然微信手动转账是目前的商业化验证手段，那么【管理后台的一键加积分】就是该手段的必然配套设施，它比接入完整的支付网关开发成本低得多，但极大改善了您的运营体验。

## 5. 验证步骤 (Verification Steps)
1. 测试将自己的账号标记为 `is_admin=True`，并尝试访问 `/admin` 页面。
2. 在管理后台测试为任意测试账号增加 100 积分，检查前端能否即时生效并用于消耗。
3. 检查注册页面，未勾选协议复选框时是否无法点击注册。
4. 使用新账号登录，检查空白聊天页面是否出现了 4 个推荐的提示词卡片，且点击能正常发送。
5. 提交一条报错反馈，检查数据库 `feedbacks` 表中是否成功记录。
