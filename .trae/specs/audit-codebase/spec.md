# 源代码及业务逻辑审计规范

## Why
为了确保系统的稳定性和可靠性，需要全面检查项目（deer-flow 及其子模块）的源代码是否存在语法、类型等错误，并评估核心业务逻辑的完整性和健壮性。

## What Changes
- 本次变更不直接修改现有业务代码，主要进行静态分析、测试执行和代码审查。
- 将产出详细的代码审计报告，列出发现的错误、测试失败项以及业务逻辑上的遗漏或潜在缺陷。

## Impact
- 受影响的模块：涉及 `backend`、`frontend` 和 `StatsPAI` 等项目核心模块。
- 纯只读和分析性操作，不对当前系统运行产生破坏性影响。

## ADDED Requirements
### Requirement: 静态代码分析
系统必须通过相应的代码检查工具（例如针对 Python 的 ruff/mypy，针对前端的 eslint/tsc）分析并记录所有的静态错误。

### Requirement: 测试套件执行
必须运行现有的单元测试和集成测试（如 pytest），记录未通过的测试用例，以此检验基本业务逻辑的正确性。

### Requirement: 核心业务逻辑深度审查
需针对后端的 API 路由处理、数据库操作、前端的状态管理以及 StatsPAI 的核心算法逻辑进行代码走查，识别错误处理缺失、边界条件未覆盖或逻辑不闭环等问题。

### Requirement: 审计报告输出
最终必须生成一份综合性的 `audit_report.md` 文件，涵盖所有审查发现及后续的修复建议。
