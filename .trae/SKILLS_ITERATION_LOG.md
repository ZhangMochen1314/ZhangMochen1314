# 科研智能体技能深度迭代方法论 (Skills Iteration Log)

本文档基于对 `DeepResValue-Spatial`（空间计量技能）的四次真实迭代过程进行复盘，提炼出了为基于 `StatsPAI` 引擎开发大模型智能体科研技能的标准“四步走”方法论。未来的所有实证分析技能（如断点回归、合成控制等）开发必须严格遵循此规范。

---

## 迭代经验：从玩具级应用到工业级学术智能体

### 阶段一：搭建骨架（确立引擎首选原则）
*   **现象**：最初的大模型倾向于使用它预训练阶段学过的原生库（如 `libpysal`, `statsmodels`），忽视了我们内置的高性能私有引擎 `StatsPAI`。
*   **动作**：在 `SKILL.md` 中强制加入 **“StatsPAI 首选原则”** 和 **“Fallback 稳健机制”**。
*   **缺陷**：模型虽然知道了名字，但因为没见过源码，开始盲猜 API 路径（API幻觉），导致沙盒疯狂报错。

### 阶段二：注入精确 API 签名（解决 API 幻觉）
*   **动作**：深入研读 `StatsPAI` 源码，将核心函数（如极大似然估计、莫兰指数）的**绝对导入路径**（例如 `from statspai.spatial.esda.moran import moran`）和**核心参数**写死进提示词中。
*   **效果**：大模型彻底停止了瞎猜，能够写出 100% 正确调用私有框架的 Python 脚本。

### 阶段三：注入前沿算法与诊断体系（拔高学术水平）
*   **现象**：模型只会跑基础的截面 OLS 扩展，不知道框架里其实藏着更高级的面板空间模型、LM 检验以及专有的学术绘图封装。
*   **动作**：
    1.  强制引入学术前置检验（如 `lm_tests`）。
    2.  强制引入高级面板估计（如 `spatial_panel`）。
    3.  强制绑定结果对象的专有画图函数（如 `moran_plot`, `lisa_cluster_map`），并要求全局执行 `set_theme('academic')`。
*   **效果**：输出的结果和图表直接达到了核心期刊的标准。

### 阶段四：增加防呆预检与底层数据约束（打造完美鲁棒性）
*   **现象**：用户上传野生数据（如缺少经纬度、有缺失值的面板）时，模型如果不加判断直接调用 `StatsPAI`，会在底层引发复杂的矩阵错误（如 Unbalanced Panel, 顺序错乱）。
*   **动作**：在 `SKILL.md` 最顶层加入 **“意图澄清与数据预检 (Data Validation & Clarification)”**：
    1.  **沙盒探针**：收到文件后必须先执行 `pd.read_csv().head()` 查结构。
    2.  **要素逼问**：如果缺关键要素（如处理变量、空间权重），强制模型“踩刹车”并主动询问用户，禁止盲跑。
    3.  **强制对齐与清洗**：在调用严格的底层函数（如 `spatial_panel`）前，明确要求大模型自己去检查平衡性和对齐矩阵。
*   **效果**：沙盒执行的 Zero-shot 成功率得到质的飞跃，系统变得极度稳定且具有启发式交互感。

---

## 结论：未来新技能开发 Checklist
针对 `StatsPAI` 引擎的任何新模块（如 RD, Synth, CausalML），开发 `SKILL.md` 时必须包含：
1.  [ ] **意图澄清**：必须预设用户可能模糊描述的场景，并写明“主动询问哪些变量”。
2.  [ ] **数据约束**：必须查阅源码，指出该模块对 DataFrame（是否要求平衡面板？是否要求某些列必须为 0/1？）的隐性要求。
3.  [ ] **绝对 API 路径**：必须给出前沿估计量（如 `gsynth`, `rdrobust`）的明确 `from ... import ...` 语句。
4.  [ ] **学术制图约束**：必须要求使用 `statspai.plots.set_theme('academic')`。
5.  [ ] **自修复机制**：必须包含遇到异常时调用 `REMEDIATIONS` 的兜底指令。
